# pytest-qt is deliberately NOT listed. Nothing under tests/ takes a `qtbot` fixture —
# conftest mocks the whole Qt/QGIS runtime instead — and tests_qgis/ runs on its own
# harness rather than under pytest, so it was never buying anything. What it cost was the
# suite: installed without PyQt it aborts *collection* ("pytest-qt requires either
# PySide6, PyQt5 or PyQt6 installed") before a single test runs, and `-p no:qt` does not
# call it off. That is invisible on CI, where the qgis/qgis:ltr image supplies PyQt, and
# fatal on any machine running the pure suite against a standalone interpreter — which is
# the whole point of mocking QGIS out. Add it back only alongside a test that needs it.

# Production dependency, not just a test one: contour_analysis imports it unguarded for
# marching squares, and keypoint_analysis for ridge skeletonisation. It was undeclared
# here, so a clean install passed and then failed the contour tests. No upper bound —
# find_contours and skeletonize are long-stable, and pinning risks fighting whatever the
# QGIS image already ships. 0.18 is the floor: from there find_contours excludes NaN
# natively, which is what stops fabricated contours along a clip boundary.
scikit-image>=0.18
# Report charts — the same undeclared-dependency trap scikit-image fell into, and it went
# unnoticed for the same reason: the QGIS image ships matplotlib, so CI was green while a
# clean local install failed 22 tests across test_report_charts and test_reporting on
# `ModuleNotFoundError: No module named 'matplotlib'`. report_charts and reporting import
# it unguarded to render the flow network, the hydrograph and the fill timeline, so it is
# a production dependency here too. No upper bound, for the reason above — pyplot and the
# Agg backend are stable, and pinning risks fighting the image's own copy.
matplotlib>=3.5
